# DATUM 达途·政途 PC工作台与后台管理端需求规格说明书

版本：V1.0  
日期：2026-08-05  
适用范围：政途一期/MVP研发  
建设范围：PC工作台、后台管理端  
暂不建设：移动端小程序、群众端服务、自动行政审批、全量事项审核、通用BI平台  

---

## 1. 文档目的

本文档用于指导 DATUM 达途·政途系统的产品设计、研发开发、测试验收和试点交付。

系统第一阶段定位为：

> 面向人社内部工作人员的 AI 政务办公与经办辅助工作台。

系统重点解决人社内部工作人员在政策查询、公文写作、数据查询、分析报告、业务预审、风险预警等工作中的效率和质量问题。

---

## 2. 产品目标

### 2.1 总体目标

建设一个面向市、县、乡镇/街道人社工作人员使用的 PC端 AI 工作台，并配套后台管理端，实现：

1. 人社政策、办事指南、业务口径的智能问答与溯源。
2. 人社公文、报告、通知、函件等材料的智能生成与审校。
3. 基于固定业务指标的自然语言问数、图表生成和分析报告生成。
4. 对就业补贴等高频事项进行 AI 辅助预审，并进入人工复核闭环。
5. 对异常数据、风险对象、待处理事项进行统一提醒和任务处置。
6. 通过后台完成知识、模板、指标、规则、权限、日志等配置管理。

### 2.2 MVP目标

MVP阶段重点完成可试点、可演示、可内部使用的最小闭环：

| 能力 | MVP交付目标 |
|---|---|
| 知识问答 | 支持人社政策与办事指南问答，答案必须引用来源 |
| 公文助手 | 支持通知、报告、请示、函件的初稿生成和Word导出 |
| 智能问数 | 支持20-30个固定高频指标自然语言查询 |
| 分析报告 | 支持月报/季报模板化生成 |
| 智能审核 | 支持1-2个就业补贴事项辅助预审 |
| 任务待办 | 支持AI结果进入人工确认、退回、归档 |
| 后台管理 | 支持用户权限、知识库、模板、指标、规则、日志管理 |

### 4.3 暂不纳入范围

| 内容 | 暂不纳入原因 |
|---|---|
| 移动端小程序 | 第一阶段聚焦PC端业务闭环，避免分散研发资源 |
| 群众端智能客服 | 政途第一阶段定位为内部工作人员使用 |

| 复杂多模型调度平台 | 属于达途云脑底座能力，不作为政途业务一期重点 |

## 5. 总体业务流程

### 5.1 知识问答闭环

流程：

1. 管理员在后台上传政策文件、办事指南、业务口径文件。
2. 系统解析文档，生成文本切片和向量索引。
3. 工作人员在PC工作台提问。
4. 系统检索相关知识片段。
5. AI生成回答，并展示引用来源、文件名称、原文片段。
6. 用户可对答案进行有用/无用反馈。
7. 管理员根据反馈优化知识库。

关键要求：

1. 答案必须显示来源依据。
2. 对未检索到依据的问题，系统应提示“暂无明确依据”，不得编造。
3. 问答记录需保存，支持审计和复盘。

### 5.2 公文办公闭环

流程：

1. 管理员维护公文模板和写作规范。
2. 用户选择公文类型，如通知、报告、请示、函件。
3. 用户输入写作主题、背景、要点、收文对象等信息。
4. AI基于模板和知识库生成初稿。
5. 系统进行错别字、格式、敏感表述、涉政表达审校。
6. 用户在线编辑。
7. 用户导出Word文档。
8. 系统保存生成记录和导出记录。

关键要求：

1. 生成内容必须允许人工编辑。
2. 涉政表述、敏感词、格式问题应高亮提示。
3. MVP阶段先支持Word导出，套红、OFD、PDF可后置。

### 5.3 数据决策闭环

流程：

1. 管理员配置数据源和指标口径。
2. 用户用自然语言提出数据查询问题。
3. 系统识别用户意图、匹配指标口径。
4. 系统查询固定数据表或接口。
5. 返回数据表格、图表和口径说明。
6. 用户可基于查询结果生成分析报告。
7. 系统输出同比、环比、趋势分析和工作建议。

关键要求：

1. MVP阶段只支持固定指标，不做无限自由查询。
2. 每个指标必须有口径说明、数据来源和更新时间。
3. 图表和报告中的数字必须可追溯到数据源。

### 5.4 审核经办闭环

流程：

1. 用户选择需要预审的业务事项。
2. 用户录入申请对象信息或上传申报材料。
3. 系统识别材料内容，调用审核规则。
4. AI输出预审建议：建议通过、建议不通过、需人工核实。
5. 系统展示判断依据、命中规则、缺失材料和风险提示。
6. 经办人员人工确认。
7. 结果进入归档或退回补正。
8. 管理员根据实际处理结果优化规则。

关键要求：

1. AI只输出辅助预审建议，不得输出最终审批决定。
2. 所有预审结果必须进入人工复核。
3. 系统必须记录AI判断依据和人工处理结果。

### 5.5 风险监管闭环

流程：

1. 系统定期或手动比对业务数据。
2. 识别重复数据、异常数据、状态变化、规则冲突。
3. 生成风险预警。
4. 预警进入任务待办。
5. 经办人员核实处理。
6. 形成风险处置台账。

关键要求：

1. MVP阶段可先做异常数据清单，不做复杂自动处置。
2. 风险等级至少分为高、中、低。
3. 每条预警必须有触发规则、数据依据和处置状态。

## 6. PC工作台功能需求

### 6.1 首页工作台

#### 功能说明

用户登录后进入首页，首页展示当前用户相关的待办、风险提醒、最近问答、常用功能和系统公告。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-HOME-001 | 工作台首页 | 展示个人待办、风险提醒、快捷入口 | P0 |
| PC-HOME-002 | 待办概览 | 展示待处理、已逾期、已完成数量 | P0 |
| PC-HOME-003 | 风险提醒 | 展示高风险预警事项 | P1 |
| PC-HOME-004 | 常用功能 | 支持用户快速进入问答、公文、问数、审核 | P0 |
| PC-HOME-005 | 最近记录 | 展示最近问答、公文、报告、审核记录 | P1 |

#### 验收标准

1. 用户登录后可看到与自己权限相关的数据。
2. 点击待办可进入对应任务详情。
3. 无权限用户不得看到其他部门数据。

### 6.2 人社知识智能问答

#### 功能说明

用户可围绕人社政策、办事指南、业务口径进行自然语言提问，系统基于知识库检索并生成可溯源答案。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-QA-001 | 新建问答 | 支持用户输入自然语言问题 | P0 |
| PC-QA-002 | 多轮对话 | 支持基于上下文继续追问 | P0 |
| PC-QA-003 | 来源引用 | 答案展示来源文件、章节、原文片段 | P0 |
| PC-QA-004 | 政策关联推荐 | 推荐相关政策、办事指南 | P1 |
| PC-QA-005 | 答案反馈 | 用户可标记有用、无用、需修正 | P0 |
| PC-QA-006 | 历史记录 | 支持查看个人问答历史 | P0 |
| PC-QA-007 | 导出问答 | 支持导出问答内容 | P2 |

#### 业务规则

1. 检索不到可信依据时，不得生成确定性答案。
2. 答案需标识“AI生成，仅供业务参考”。
3. 涉及审批结论、资格判断的问题，需引导用户进入智能审核模块。

#### 验收标准

1. 常见政策问题可返回准确答案。
2. 答案必须展示至少一个引用来源。
3. 用户反馈可在后台查看。

### 6.3 AI公文助手

#### 功能说明

支持用户基于公文类型、业务场景、输入要点生成公文初稿，并进行审校、编辑和导出。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-DOC-001 | 公文类型选择 | 支持通知、报告、请示、函件、批复等 | P0 |
| PC-DOC-002 | 模板生成 | 基于后台模板生成公文初稿 | P0 |
| PC-DOC-003 | 要点输入 | 支持输入主题、背景、事项、要求、时间等 | P0 |
| PC-DOC-004 | AI续写/改写 | 支持润色、扩写、压缩、转换语气 | P1 |
| PC-DOC-005 | 合规审校 | 检查错别字、敏感词、涉政表述、格式问题 | P0 |
| PC-DOC-006 | 在线编辑 | 支持用户修改生成内容 | P0 |
| PC-DOC-007 | Word导出 | 支持导出为Word文件 | P0 |
| PC-DOC-008 | 生成记录 | 保存生成、编辑、导出记录 | P0 |

#### 业务规则

1. 公文生成必须基于模板，不能完全自由生成。
2. 所有导出文档应保留生成记录。
3. 涉政敏感内容必须提示人工确认。

#### 验收标准

1. 用户选择模板并输入要点后，可生成完整公文初稿。
2. 审校结果可定位到具体段落或句子。
3. 导出的Word文档格式基本可用。

### 6.4 智能问数

#### 功能说明

用户通过自然语言查询已配置的业务指标，系统返回数据结果、图表和指标口径说明。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-DATA-001 | 自然语言问数 | 输入“本月就业困难人员补贴发放人数是多少”等问题 | P0 |
| PC-DATA-002 | 指标识别 | 匹配后台配置的指标口径 | P0 |
| PC-DATA-003 | 数据查询 | 查询固定数据源或数据表 | P0 |
| PC-DATA-004 | 图表生成 | 自动生成柱状图、折线图、饼图等 | P0 |
| PC-DATA-005 | 口径解释 | 展示指标定义、数据来源、更新时间 | P0 |
| PC-DATA-006 | 结果导出 | 支持导出Excel或图片 | P1 |
| PC-DATA-007 | 追问分析 | 支持对当前结果继续追问 | P1 |

#### 业务规则

1. 只允许查询用户有权限的数据。
2. 未配置口径的指标，提示用户联系管理员配置。
3. 数字、图表、报告必须使用同一数据来源。

#### 验收标准

1. MVP支持20-30个高频指标。
2. 查询结果展示指标口径和数据更新时间。
3. 同一问题多次查询结果一致。

### 6.5 智能分析报告

#### 功能说明

基于固定数据指标和报告模板，自动生成月报、季报、专题分析报告。

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|

| PC-RPT-002 | 数据周期选择 | 支持选择月份、季度、年度 | P0 |
| PC-RPT-003 | 自动取数 | 根据模板自动获取指标数据 | P0 |
| PC-RPT-004 | 同比环比分析 | 自动生成同比、环比变化说明 | P0 |
| PC-RPT-005 | 工作建议 | 根据数据异常和趋势生成建议 | P1 |
| PC-RPT-006 | 报告编辑 | 支持人工修改报告内容 | P0 |
| PC-RPT-007 | Word导出 | 支持导出报告 | P0 |

#### 功能说明

支持对新政策进行摘要、要点提取、新旧政策对比、地区政策横向对比和解读报告生成。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-POL-001 | 政策摘要 | 自动提取政策背景、对象、条件、标准、流程 | P1 |
| PC-POL-002 | 新旧对比 | 对比同类政策差异 | P1 |
| PC-POL-003 | 地区对比 | 对比不同地区政策差异 | P2 |
| PC-POL-004 | 解读报告 | 生成政策解读初稿 | P1 |

1. 政策摘要结构清晰。
2. 对比结果能显示差异条目和来源依据。
3. 政策标签建议需支持人工确认后入库。

#### 功能说明

#### MVP试点事项建议

1. 就业补贴资格预审。
2. 灵活就业社保补贴资格核查。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-AUDIT-001 | 事项选择 | 选择预审事项 | P0 |
| PC-AUDIT-002 | 对象信息录入 | 录入人员或企业基本信息 | P0 |
| PC-AUDIT-003 | 材料上传 | 上传身份证明、申请表、证明材料等 | P0 |
| PC-AUDIT-004 | 材料识别 | 识别材料字段和关键信息 | P0 |
| PC-AUDIT-005 | 规则校验 | 根据后台规则进行资格校验 | P0 |
| PC-AUDIT-006 | 预审结论 | 输出建议通过、建议不通过、需人工核实 | P0 |
| PC-AUDIT-007 | 原因解释 | 展示命中规则和判断依据 | P0 |
| PC-AUDIT-008 | 人工复核 | 经办人员确认、退回或归档 | P0 |

1. 预审结论不得作为最终审批结论。
2. 人工复核前，预审任务不得归档完成。

4. 规则冲突时，系统应标记为需人工核实。

#### 验收标准

1. 至少支持一个试点事项从材料上传到人工确认的完整流程。
2. 每条预审结果均有判断原因。
3. 人工处理结果可回写任务状态。

## 10. AI能力要求

### 10.1 RAG问答要求

1. 支持文档解析、切片、向量化、召回、重排序、生成。
2. 答案必须附带引用来源。
3. 支持无答案兜底，不允许无依据编造。
4. 支持知识反馈和人工修正。

### 10.2 公文生成要求

1. 基于模板生成，不做完全开放式生成。
2. 支持不同公文类型的Prompt模板。
3. 支持审校规则。
4. 支持人工编辑和导出。

### 10.3 问数要求

1. 自然语言先映射到指标。
2. 指标必须来自后台已配置口径。
3. 查询SQL或接口调用不得由大模型自由生成并直接执行。
4. 重要查询需记录日志。

### 10.4 智能审核要求

1. 规则判断优先，AI解释辅助。
2. AI不得直接作出最终审批决定。
3. AI预审必须展示命中规则。
4. 结果必须进入人工复核流程。

## 12. 非功能需求

### 12.1 性能要求

| 场景 | 要求 |
|---|---|
| 普通知识问答 | 10秒内返回首屏结果 |
| 公文生成 | 30秒内生成初稿 |
| 固定指标问数 | 5秒内返回结构化数据 |
| 分析报告生成 | 60秒内生成报告 |
| 审核预审 | 30秒内输出预审建议 |
| 首页加载 | 3秒内完成主要内容展示 |

### 12.2 安全要求

1. 支持账号密码或统一身份认证。
2. 支持角色权限和数据权限。
3. 敏感信息脱敏展示。
4. 文件上传需校验格式和大小。
5. 所有导出、删除、规则修改操作必须记录日志。
6. 支持私有化部署，数据不出域。

### 12.3 可用性要求

1. PC端兼容主流浏览器。
2. 页面设计应适合政务办公，简洁、清晰、可扫描。
3. AI生成内容必须支持人工修改。
4. 错误提示应明确可理解。

### 12.4 可维护性要求

1. 政策、模板、指标、规则应后台可配置。
2. AI Prompt应可版本管理。
3. 审核规则应支持版本发布和回滚。
4. 日志应支持检索和导出。

### 13.1 MVP总体验收

| 验收项 | 标准 |
|---|---|

## 15. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 功能范围膨胀 | 延期、质量下降 | MVP只做PC端和后台，固定4个核心场景 |
| 数据源无法接入 | 问数、审核无法真实运行 | 先用样例数据，尽早完成数据接口盘点 |
| 政策知识不完整 | 问答准确率低 | 优先整理高频政策和办事指南 |
| 审核责任不清 | 行政风险 | 明确AI只做辅助预审，必须人工确认 |
| 指标口径争议 | 数据结果不被认可 | 建立指标口径库，由业务部门确认 |
| 公文内容不合规 | 涉政表达风险 | 建立模板库和审校规则，人工最终确认 |
| 权限控制不足 | 数据安全风险 | P0阶段必须建设RBAC、数据权限、日志审计 |

## 17. 结论

政途第一阶段的研发重点不是把所有AI能力一次性做全，而是先完成一个可交付、可试点、可验收的内部PC端AI工作台。

建议第一版围绕四个核心场景推进：

1. 问政策。
2. 写公文。
3. 查数据。
4. 做预审。

同时必须配套后台的知识、模板、指标、规则、权限、日志能力。只有这样，系统才能从“AI演示工具”变成真正可用于人社内部工作的业务系统。
