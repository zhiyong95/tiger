# DATUM 达途·政途 PC工作台与后台管理端需求规格说明书

版本：V1.1  
日期：2026-08-07  
适用范围：政途一期/MVP研发  
建设范围：PC工作台、后台管理端  
暂不建设：移动端小程序、群众端服务、自动行政审批、全量事项审核、通用BI平台  

---

## 1. 文档目的

本文档用于指导 DATUM 达途·政途系统的产品设计、研发开发、测试验收和试点交付。

系统第一阶段定位为：

> 面向人社内部工作人员的 AI 政务办公与经办辅助工作台。

系统重点解决人社内部工作人员在政策查询、公文写作、数据查询、分析报告、业务预审、风险预警等工作中的效率和质量问题。

---

## 2. 产品目标

### 2.1 总体目标

建设一个面向市、县、乡镇/街道人社工作人员使用的 PC端 AI 工作台，并配套后台管理端，实现：

1. 人社政策、办事指南、业务口径的智能问答与溯源。
2. 人社公文、报告、通知、函件等材料的智能生成与审校。
3. 基于固定业务指标的自然语言问数、图表生成和分析报告生成。
4. 对就业补贴等高频事项进行 AI 辅助预审，并进入人工复核闭环。
5. 对异常数据、风险对象、待处理事项进行统一提醒和任务处置。
6. 通过后台完成知识、模板、指标、规则、权限、日志等配置管理。

### 2.2 MVP目标

MVP阶段重点完成可试点、可演示、可内部使用的最小闭环：

| 能力 | MVP交付目标 |
|---|---|
| 知识问答 | 支持人社政策与办事指南问答，答案必须引用来源 |
| 公文助手 | 支持通知、报告、请示、函件的初稿生成和Word导出 |
| 智能问数 | 支持20-30个固定高频指标自然语言查询 |
| 分析报告 | 支持月报/季报模板化生成 |
| 智能审核 | 支持1-2个就业补贴事项辅助预审 |
| 任务待办 | 支持AI结果进入人工确认、退回、归档 |
| 后台管理 | 支持用户权限、知识库、模板、指标、规则、日志管理 |

1. 首页工作台
2. 人社知识智能问答
3. AI公文助手
4. 智能问数
5. 智能分析报告
6. 政策快研
7. 业务智能审核
8. 风险预警与任务待办
9. 个人中心

### 4.2 后台管理端

后台管理端面向管理员和运营人员，包含：

1. 用户、角色、部门权限管理
2. 知识库管理
3. 公文模板管理
4. 政策标签管理
5. 指标口径管理
6. 审核规则管理
7. 数据源管理
8. 任务流配置
9. 日志审计
10. 系统参数配置

### 4.3 暂不纳入范围

| 内容 | 暂不纳入原因 |
|---|---|
| 移动端小程序 | 第一阶段聚焦PC端业务闭环，避免分散研发资源 |
| 群众端智能客服 | 政途第一阶段定位为内部工作人员使用 |
| 全量业务事项审核 | 审核规则复杂，先选择高频事项打样 |
| 自动审批 | 涉及行政责任，AI只做辅助建议 |
| 完全自由BI | 数据口径难控，先做固定指标问数 |
| 复杂多模型调度平台 | 属于达途云脑底座能力，不作为政途业务一期重点 |

## 5. 总体业务流程

### 5.1 知识问答闭环

流程：

1. 管理员在后台上传政策文件、办事指南、业务口径文件。
2. 系统解析文档，生成文本切片和向量索引。
3. 工作人员在PC工作台提问。
4. 系统检索相关知识片段。
5. AI生成回答，并展示引用来源、文件名称、原文片段。
6. 用户可对答案进行有用/无用反馈。
7. 管理员根据反馈优化知识库。

关键要求：

1. 答案必须显示来源依据。
2. 对未检索到依据的问题，系统应提示“暂无明确依据”，不得编造。
3. 问答记录需保存，支持审计和复盘。

### 5.2 公文办公闭环

流程：

1. 管理员维护公文模板和写作规范。
2. 用户选择公文类型，如通知、报告、请示、函件。
3. 用户输入写作主题、背景、要点、收文对象等信息。
4. AI基于模板和知识库生成初稿。
5. 系统进行错别字、格式、敏感表述、涉政表达审校。
6. 用户在线编辑。
7. 用户导出Word文档。
8. 系统保存生成记录和导出记录。

关键要求：

1. 生成内容必须允许人工编辑。
2. 涉政表述、敏感词、格式问题应高亮提示。
3. MVP阶段先支持Word导出，套红、OFD、PDF可后置。

### 5.3 数据决策闭环

流程：

1. 管理员配置数据源和指标口径。
2. 用户用自然语言提出数据查询问题。
3. 系统识别用户意图、匹配指标口径。
4. 系统查询固定数据表或接口。
5. 返回数据表格、图表和口径说明。
6. 用户可基于查询结果生成分析报告。
7. 系统输出同比、环比、趋势分析和工作建议。

关键要求：

1. MVP阶段只支持固定指标，不做无限自由查询。
2. 每个指标必须有口径说明、数据来源和更新时间。
3. 图表和报告中的数字必须可追溯到数据源。

### 5.4 审核经办闭环

流程：

1. 用户选择需要预审的业务事项。
2. 用户录入申请对象信息或上传申报材料。
3. 系统识别材料内容，调用审核规则。
4. AI输出预审建议：建议通过、建议不通过、需人工核实。
5. 系统展示判断依据、命中规则、缺失材料和风险提示。
6. 经办人员人工确认。
7. 结果进入归档或退回补正。
8. 管理员根据实际处理结果优化规则。

关键要求：

1. AI只输出辅助预审建议，不得输出最终审批决定。
2. 所有预审结果必须进入人工复核。
3. 系统必须记录AI判断依据和人工处理结果。

### 5.5 风险监管闭环

流程：

1. 系统定期或手动比对业务数据。
2. 识别重复数据、异常数据、状态变化、规则冲突。
3. 生成风险预警。
4. 预警进入任务待办。
5. 经办人员核实处理。
6. 形成风险处置台账。

关键要求：

1. MVP阶段可先做异常数据清单，不做复杂自动处置。
2. 风险等级至少分为高、中、低。
3. 每条预警必须有触发规则、数据依据和处置状态。

## 6. PC工作台功能需求

### 6.1 首页工作台

#### 功能说明

用户登录后进入首页，首页展示当前用户相关的待办、风险提醒、最近问答、常用功能和系统公告。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-HOME-001 | 工作台首页 | 展示个人待办、风险提醒、快捷入口 | P0 |
| PC-HOME-002 | 待办概览 | 展示待处理、已逾期、已完成数量 | P0 |
| PC-HOME-003 | 风险提醒 | 展示高风险预警事项 | P1 |
| PC-HOME-004 | 常用功能 | 支持用户快速进入问答、公文、问数、审核 | P0 |
| PC-HOME-005 | 最近记录 | 展示最近问答、公文、报告、审核记录 | P1 |

#### 验收标准

1. 用户登录后可看到与自己权限相关的数据。
2. 点击待办可进入对应任务详情。
3. 无权限用户不得看到其他部门数据。

### 6.2 人社知识智能问答

#### 功能说明

用户可围绕人社政策、办事指南、业务口径进行自然语言提问，系统基于知识库检索并生成可溯源答案。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-QA-001 | 新建问答 | 支持用户输入自然语言问题 | P0 |
| PC-QA-002 | 多轮对话 | 支持基于上下文继续追问 | P0 |
| PC-QA-003 | 来源引用 | 答案展示来源文件、章节、原文片段 | P0 |
| PC-QA-004 | 政策关联推荐 | 推荐相关政策、办事指南 | P1 |
| PC-QA-005 | 答案反馈 | 用户可标记有用、无用、需修正 | P0 |
| PC-QA-006 | 历史记录 | 支持查看个人问答历史 | P0 |
| PC-QA-007 | 导出问答 | 支持导出问答内容 | P2 |

#### 业务规则

1. 检索不到可信依据时，不得生成确定性答案。
2. 答案需标识“AI生成，仅供业务参考”。
3. 涉及审批结论、资格判断的问题，需引导用户进入智能审核模块。

#### 验收标准

1. 常见政策问题可返回准确答案。
2. 答案必须展示至少一个引用来源。
3. 用户反馈可在后台查看。

### 6.3 AI公文助手

#### 功能说明

支持用户基于公文类型、业务场景、输入要点生成公文初稿，并进行审校、编辑和导出。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |
|---|---|---|---|
| PC-DOC-001 | 公文类型选择 | 支持通知、报告、请示、函件、批复等 | P0 |
| PC-DOC-002 | 模板生成 | 基于后台模板生成公文初稿 | P0 |
| PC-DOC-003 | 要点输入 | 支持输入主题、背景、事项、要求、时间等 | P0 |
| PC-DOC-004 | AI续写/改写 | 支持润色、扩写、压缩、转换语气 | P1 |
| PC-DOC-005 | 合规审校 | 检查错别字、敏感词、涉政表述、格式问题 | P0 |
| PC-DOC-006 | 在线编辑 | 支持用户修改生成内容 | P0 |
| PC-DOC-007 | Word导出 | 支持导出为Word文件 | P0 |
| PC-DOC-008 | 生成记录 | 保存生成、编辑、导出记录 | P0 |

#### 业务规则

1. 公文生成必须基于模板，不能完全自由生成。
2. 所有导出文档应保留生成记录。
3. 涉政敏感内容必须提示人工确认。

#### 验收标准

1. 用户选择模板并输入要点后，可生成完整公文初稿。
2. 审校结果可定位到具体段落或句子。
3. 导出的Word文档格式基本可用。

### 6.4 智能问数

#### 功能说明

用户通过自然语言查询已配置的业务指标，系统返回数据结果、图表和指标口径说明。

#### 功能点

| 编号 | 功能点 | 说明 | 优先级 |

## 9. 权限要求

### 9.1 权限设计原则

系统采用“角色权限 + 数据权限 + 资源权限 + 操作审计”的组合权限模型。

权限设计原则如下：

1. 默认最小权限：用户只拥有完成本岗位工作所需权限。
2. 前后端双重校验：前端控制菜单和按钮展示，后端必须再次校验接口权限。
3. 数据按组织和区域隔离：不同部门、不同区划、不同业务线的数据默认隔离。
4. AI结果权限跟随业务数据权限：用户无权查看的数据，不得通过AI问答、问数、报告、审核间接获取。
5. 关键操作必须留痕：导出、删除、发布、下架、规则变更、权限变更、AI审核确认均需记录日志。

### 9.2 权限维度

| 权限维度 | 控制对象 | 示例 |
|---|---|---|
| 菜单权限 | 用户可见的一级、二级菜单 | 是否显示智能问数、后台管理、日志审计 |
| 按钮权限 | 页面内具体操作按钮 | 新增、编辑、删除、导出、发布、下架、人工确认 |
| 数据权限 | 用户可访问的数据范围 | 本人、本部门、本辖区、全部 |
| 知识权限 | 用户可检索的知识库范围 | 就业政策库、社保政策库、人才政策库、内部口径库 |
| 指标权限 | 用户可查询的指标范围 | 就业指标、社保指标、补贴指标、风险指标 |

| 导出 | 导出Word、Excel、日志、报告 | 按功能授权开放，必须记录日志 |
| 人工确认 | 确认AI预审建议或风险处置结果 | 经办人员、乡镇/街道经办员、科室负责人 |
| 退回补正 | 将预审任务退回补充材料 | 经办人员、乡镇/街道经办员 |
| 转办 | 将任务转给其他人员 | 经办人员、科室负责人 |
| 归档 | 完成任务并归档 | 经办人员、科室负责人 |
| 权限分配 | 分配角色、菜单、数据范围 | 系统管理员 |

### 9.7 数据权限规则

数据权限按“行政区划 + 部门 + 业务线 + 数据敏感等级”共同判断。

| 数据范围 | 说明 | 适用角色 |
|---|---|---|
| 本人数据 | 只查看本人创建、处理、收藏、导出的数据 | 普通业务人员 |
| 本部门数据 | 查看本部门人员产生或归属本部门的数据 | 普通业务人员、科室负责人 |
| 本窗口数据 | 查看本窗口受理、处理的业务数据 | 窗口经办人员 |
| 本辖区数据 | 查看本乡镇/街道或授权区划范围内的数据 | 乡镇/街道经办员 |
| 本业务线数据 | 查看就业、社保、人才等授权业务线数据 | 业务管理员、科室负责人 |
| 汇总数据 | 只查看统计汇总，不查看个人明细 | 局领导/分管领导 |
| 全部数据 | 查看系统全部配置和业务数据 | 系统管理员按需授权 |

数据权限规则：

1. 人员姓名、身份证号、手机号、银行卡号等敏感字段默认脱敏。
2. 局领导默认查看汇总和趋势，不默认查看个人敏感明细。
3. 审计人员查看日志时，可看到操作对象，但敏感业务字段按审计授权展示。
4. 用户通过智能问答、智能问数、分析报告获取数据时，也必须执行同样的数据权限过滤。
5. 数据导出需要校验导出权限，并记录导出人、导出时间、导出范围、导出原因。

### 9.8 知识库权限规则

| 权限项 | 说明 |
|---|---|
| 知识库可见范围 | 用户只能检索有权限的知识库 |
| 文档状态 | 只有已发布文档可被普通用户检索 |
| 内部口径 | 内部口径类知识默认只对内部授权人员开放 |
| 反馈处理 | 用户可提交反馈，业务管理员可处理反馈 |
| 版本回溯 | 管理员可查看历史版本，普通用户不可见 |

### 9.9 AI能力权限规则

| AI能力 | 权限控制要求 |
|---|---|
| 知识问答 | 受知识库权限限制，回答只能引用用户有权访问的文档 |
| 公文生成 | 受模板权限限制，用户只能使用授权模板 |
| 智能问数 | 受指标权限和数据权限限制，不允许绕过权限查询明细 |
| 分析报告 | 受报告模板、指标和数据范围限制 |
| 政策快研 | 受政策库权限限制，内部政策研究材料需单独授权 |
| 智能审核 | 受事项权限限制，用户只能发起或处理授权事项 |
| 风险预警 | 受任务归属、辖区和部门权限限制 |

### 9.10 权限校验流程

用户访问系统时，权限校验流程如下：

1. 用户登录，系统识别用户身份、部门、角色、行政区划、业务线。
2. 系统加载该用户可见菜单。
3. 用户进入页面时，前端根据菜单权限和按钮权限展示操作入口。
4. 用户调用接口时，后端校验接口权限、按钮权限和数据权限。
5. 涉及AI调用时，系统先过滤用户可访问知识、指标、事项和数据，再调用AI能力。
6. 涉及导出、发布、删除、人工确认等关键操作时，系统记录审计日志。
7. 权限不足时，系统提示“无权限访问该功能或数据”，不得返回敏感数据。

## 10. AI能力要求

### 10.1 RAG问答要求

1. 支持文档解析、切片、向量化、召回、重排序、生成。
2. 答案必须附带引用来源。
3. 支持无答案兜底，不允许无依据编造。
4. 支持知识反馈和人工修正。

### 10.2 公文生成要求

1. 基于模板生成，不做完全开放式生成。
2. 支持不同公文类型的Prompt模板。
3. 支持审校规则。
4. 支持人工编辑和导出。

### 10.3 问数要求

1. 自然语言先映射到指标。
2. 指标必须来自后台已配置口径。
3. 查询SQL或接口调用不得由大模型自由生成并直接执行。
4. 重要查询需记录日志。

### 10.4 智能审核要求

1. 规则判断优先，AI解释辅助。
2. AI不得直接作出最终审批决定。
3. AI预审必须展示命中规则。
4. 结果必须进入人工复核流程。

### 11.1 内部接口

| 接口类型 | 说明 |
|---|---|

### 11.2 外部系统集成

4. 企业/工商数据。
5. 岗位/招聘数据。
6. 统一身份认证系统。

## 12. 非功能需求

### 12.1 性能要求

| 场景 | 要求 |
|---|---|
| 普通知识问答 | 10秒内返回首屏结果 |
| 公文生成 | 30秒内生成初稿 |
| 固定指标问数 | 5秒内返回结构化数据 |
| 分析报告生成 | 60秒内生成报告 |
| 审核预审 | 30秒内输出预审建议 |
| 首页加载 | 3秒内完成主要内容展示 |

### 12.2 安全要求

1. 支持账号密码或统一身份认证。
2. 支持角色权限和数据权限。
3. 敏感信息脱敏展示。
4. 文件上传需校验格式和大小。
5. 所有导出、删除、规则修改操作必须记录日志。
6. 支持私有化部署，数据不出域。

### 12.3 可用性要求

1. PC端兼容主流浏览器。
2. 页面设计应适合政务办公，简洁、清晰、可扫描。
3. AI生成内容必须支持人工修改。
4. 错误提示应明确可理解。

### 12.4 可维护性要求

1. 政策、模板、指标、规则应后台可配置。
2. AI Prompt应可版本管理。
3. 审核规则应支持版本发布和回滚。
4. 日志应支持检索和导出。

## 13. 验收标准

### 13.1 MVP总体验收

| 验收项 | 标准 |
|---|---|
| PC工作台 | 用户可登录并使用核心功能 |
| 后台管理端 | 管理员可配置知识、模板、指标、规则、用户 |
| 知识问答 | 常见政策问题可准确回答并引用来源 |
| 公文助手 | 可生成并导出可编辑Word文档 |
| 智能问数 | 支持20-30个固定指标查询 |
| 分析报告 | 可生成月报或专题报告初稿 |
| 智能审核 | 至少1个事项跑通AI预审到人工确认 |
| 日志审计 | 关键操作和AI调用有记录 |
| 权限控制 | 不同角色看到不同菜单和数据 |

### 13.2 AI效果验收

1. 政策问答准确率达到试点业务人员认可。
2. 问答引用来源准确。
3. 公文生成内容结构完整、语言基本符合政务表达。
4. 审核预审能正确识别明显不符合、材料缺失、需人工核实等情况。
5. AI无法确认时，应倾向输出“需人工核实”，而不是强行判断。

## 15. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 功能范围膨胀 | 延期、质量下降 | MVP只做PC端和后台，固定4个核心场景 |
| 数据源无法接入 | 问数、审核无法真实运行 | 先用样例数据，尽早完成数据接口盘点 |
| 政策知识不完整 | 问答准确率低 | 优先整理高频政策和办事指南 |
| 审核责任不清 | 行政风险 | 明确AI只做辅助预审，必须人工确认 |
| 指标口径争议 | 数据结果不被认可 | 建立指标口径库，由业务部门确认 |
| 公文内容不合规 | 涉政表达风险 | 建立模板库和审校规则，人工最终确认 |
| 权限控制不足 | 数据安全风险 | P0阶段必须建设RBAC、数据权限、日志审计 |

## 17. 结论

政途第一阶段的研发重点不是把所有AI能力一次性做全，而是先完成一个可交付、可试点、可验收的内部PC端AI工作台。

建议第一版围绕四个核心场景推进：

1. 问政策。
2. 写公文。
3. 查数据。
4. 做预审。

同时必须配套后台的知识、模板、指标、规则、权限、日志能力。只有这样，系统才能从“AI演示工具”变成真正可用于人社内部工作的业务系统。
