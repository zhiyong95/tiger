## 1. 引言

### 1.1 编写目的

本文档定义"政途 · AI政务办公工作台（达途）"的功能需求与非功能需求，作为产品设计、开发、测试、验收的依据。读者对象包括：产品经理、前后端研发工程师、测试工程师、项目实施人员及人社业务主管部门。

### 1.2 项目背景

人社部门日常工作涉及知识答疑、公文起草、数据查询、政策研判、业务审核等大量重复性、规则密集型事务。本系统以大语言模型（LLM）能力为底座，面向人社内部工作人员，提供一体化的 AI 政务办公与经办辅助工作台，覆盖"知识问答—公文处理—数据查询—分析报告—政策研判—业务审核—任务待办"全流程，并配套后台管理端对知识库、模板、规则、指标、数据源、权限与日志进行统一治理。

### 1.3 产品定位

- **产品性质**：面向人社内部工作人员的 AI 政务办公与经办辅助系统（B 端工作台）。
- **核心价值**：提升经办效率、降低合规风险、沉淀政务知识、辅助科学决策。
- **形态**：PC 端 Web 工作台（本版本）+ 后台管理端；后续对接劳动力信息采集小程序等外部数据采集端。

### 1.4 用户角色

| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 经办人员 | 县/乡镇街道一线办事人员 | 快速答疑、生成公文、查询数据、完成审核任务 |
| 业务骨干 | 市/县科室业务人员 | 政策研判、分析报告、风险处置、任务分派 |
| 部门管理者 | 处/科室负责人 | 看板监测、任务督办、效果统计 |
| 系统管理员 | 平台运维/信息中心 | 用户权限、知识库、模板、规则、指标、数据源、审计 |

### 1.5 术语与定义

| 术语 | 定义 |
|---|---|
| 工作台 | 面向经办人员的 PC 办公主界面 |
| 途途 | 系统内置 AI 助手的统一拟人化名称 |
| 智能问数 | 以自然语言查询统计数据并可视化的能力 |
| 政策研判 | 对单一政策文档进行 AI 解读分析 |
| 政策比对 | 对两份及以上政策文档进行差异比对分析 |
| 政策编制 | AI 辅助起草政策文件草案 |
| 流式输出 | 后端通过 SSE 逐字返回、前端打字机式渲染的生成方式 |
| 规则 | 采集/审核等业务中用于校验或判定的条件集合 |
| 历史报告 | 用户每次生成并保存的报告/对话记录，可恢复完整交互上下文 |

### 1.6 参考与约束

- 后端规划：Java + SpringBoot（当前前端使用 Mock API 模拟，接口设计需与 Mock 保持一致）。
- 所有 AI 生成内容必须标注"仅供参考"，并支持人工复核。
- 政务数据敏感，涉及身份证、手机号等个人信息须脱敏展示。

## 2. 总体描述

### 2.1 系统总体架构

系统由两大功能区构成：

```
达途 AI政务办公工作台
├── PC 工作台（经办/办公端）
│   ├── 首页工作台 Dashboard
│   ├── 人社知识智能问答 QA
│   ├── AI 公文助手 Document
│   ├── 智能问数 DataQuery（支持语音/文字输入）
│   ├── 智能分析报告 Report（智能报告 / 调研分析报告 / 数据分析报告）
│   ├── 政策快研 Policy（政策研判 / 政策比对 / 政策编制 / 政策问答）
│   ├── 业务智能审核 Audit
│   └── 风险预警与任务待办 Task
│
└── 后台管理端 Admin
    ├── 管理首页
    ├── 用户与权限管理
    ├── 知识库管理
    ├── 公文模板管理
    ├── 指标口径管理
    ├── 审核规则管理
    ├── 任务流配置
    ├── 政策标签管理
    ├── 数据源管理
    ├── 日志审计
    ├── 反馈管理
    └── 系统设置
```

### 2.2 技术架构

| 层 | 技术选型 |
|---|---|
| 前端框架 | Vue 3.5 + TypeScript 5.7（`<script setup>` + Composition API） |
| 构建工具 | Vite 6 |
| UI 组件库 | Element Plus 2.14 |
| 状态管理 | Pinia 3 |
| 路由 | Vue Router 4 |
| 图表 | ECharts 5 |
| 包管理 | pnpm（禁止 npm/yarn） |
| 文件导出 | file-saver、xlsx |
| 后端 | Java + SpringBoot（规划）；当前 Mock API（`src/api/mock.ts`） |
| AI 能力 | Coze 平台 Bot / Workflow（OpenAPI 调用，支持 SSE 流式） |

### 2.3 用户登录与访问

- 支持账号密码登录，登录后进入工作台。
- 顶部全局导航栏：Logo、主导航、搜索、消息通知、用户头像（含个人中心、退出）。
- 侧边栏菜单支持展开/收起（宽度 220–240px / 64px，平滑过渡）。

### 2.4 通用交互约定

- 页面切换 fade 过渡；卡片悬停轻微上浮 + 阴影加深。
- AI 对话统一采用左右气泡布局：用户消息靠右浅蓝底，AI 消息靠左白底 + 蓝色左边线，均带时间戳。
- AI 生成中显示打字/加载动画，完成后自动滚动到最新消息。
- AI 生成内容区域统一标注"AI 生成内容仅供参考，请结合实际情况审核使用"。
- 报告/公文支持导出（Word / PDF / Markdown / 文本 / Excel，按模块差异提供）。
- 响应式：大屏左右分栏，窄屏上下堆叠。

| POL-C-02 | 比对类型：新旧政策比对 / 相似政策比对。 |
| POL-C-03 | 右侧为对话形式，消息可滚动，用户靠右 AI 靠左气泡带时间戳。 |
| POL-C-04 | 点击"开始比对分析"自动拼装指令："请对以下政策进行比对分析。比对类型：…；政策1：…；政策2：…；比对维度：…；输出偏好：…。"（空配置项省略）。 |
| POL-C-05 | AI 回复至少包含：比对概览（类型、文件信息（文件名/文号/发布单位/施行日期/效力状态，能识别则展示）、差异点/相同点/变更项数量统计）；差异对比表（维度/政策A/政策B/差异结论）；AI 分析结论（影响分析、成因解读、风险提示）；变化总结报告。 |
| POL-C-06 | 变化总结按场景差异化：新旧政策比对输出修订要点、主要变化（金额提高/范围扩大/权限下放/条款新增废止等）、过渡期与新旧衔接建议、对执行影响；相似政策比对输出相似度评估、核心差异、适用场景与对象、选用建议。 |

> 对接劳动力信息采集小程序，管理采集字段校验规则与数据质量。建议作为独立一级模块"劳动力采集管理"，下设三个子页。

|---|---|

| LAB-03 | **校验日志与异常数据（对账）**：集中展示采集校验出的问题数据，按异常类型分类——字段冲突（如人员类别为机关事业单位人员但就业单位为民营企业）、字段缺失/不完整、越界/格式错误；支持按类型/模块/状态/时间筛选、查看详情（冲突字段左右对照 + 命中规则 + 整改建议）、批量整改、处理状态流转、采集数据自动改判审计留痕。 |

- 个人信息采集：基础信息（身份证、姓名、电话、出生日期/性别回显、民族、政治面貌、婚姻状况、学历、户口性质、户口/常住地地址、人员类别及联动等 18 项）、就失业信息（就业登记：单位就业/灵活就业/自主创业/公益性岗位安置/居家种养殖各分支字段；失业登记：失业原因/类型/日期/保险金/求职创业意愿等）、技能培训信息、采集员信息。
- 企业信息采集：单位基础信息（统一社会信用代码、单位名称、类型、行业、注册/经营地、从业人数、资产/营收、法人信息、十大产业、经济类型、单位状态等 26 项）、空岗信息（岗位类型、工种、人数、时间、薪资、学历/经验/语言要求等 20 项）、采集员信息。
- 高校毕业生实名制字段与个人采集字段的映射对照。
